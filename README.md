# job-search-pipeline

job-search-pipeline pulls open postings straight from employers' applicant tracking systems each night, screens them against rules you write down once, and emails you a digest of the new roles worth reading.

I built it during my own search for roles in AI literacy and learning leadership. Job boards and aggregators kept showing me postings that had closed weeks earlier, and keyword alerts surfaced roles I could never be hired into, such as jobs that required ten years in a field I have never worked in. This pipeline reads each employer's own board, so every posting in the digest was open when the run started. The screening rules are explicit, and every judgement call the filter makes on your behalf is listed in the digest so you can overrule it.

## Demo

A sample digest, generated by the code from fictional postings, is in [docs/sample_digest.md](docs/sample_digest.md). Each match shows the title, employer, work arrangement, pay band when one is published, the opening of the description, and the link to the employer's posting. Below the matches are two audit lists: postings the filter rejected on a stated requirement, and on-site roles near you that are not remote.

## What it does

1. **Pull.** Reads public job feeds from Greenhouse, Lever, Ashby, Workday, Workable, Eightfold, Oracle Cloud Recruiting, SAP SuccessFactors, iCIMS, Phenom People, and Madgex RSS boards, plus Indeed job-alert emails over IMAP. Each vendor's response is converted to one common record.
2. **Screen.** Applies the rules in your screening profile: title signals and title disqualifiers, a salary floor, years-of-experience gates in fields you have never held, licensure and clearance blockers, a remote-only rule, residency clauses ("must live in California"), and a home area for on-site roles.
3. **Diff.** Compares against `seen.json`, so each digest holds only postings you have not seen before. Roles you record as applied to stop resurfacing.
4. **Report.** Writes `digest.md` and emails it. On days with nothing new it sends a one-line status email, so a missing email means the scheduled run failed. A per-board health table flags any board that returned nothing or far fewer postings than usual.

For large Workday boards the monitor screens titles first and fetches full descriptions only for the titles that pass. On a board with 2,000 open roles, that usually means a handful of detail requests.

## Hardware required

Any computer that can run Python 3.10 or later and stay on (or wake) at the scheduled time. It has run nightly on a Windows laptop through Task Scheduler. It also runs on Linux and macOS.

## Software required

- Python 3.10 or later (tested on 3.10 and 3.12). No third-party packages; everything uses the standard library.
- An email account that allows SMTP with an app password, for sending the digest. The defaults are set for Gmail.
- Optional: IMAP access to the same mailbox, if you want Indeed job-alert emails included.

## Installation

1. Download the code.

   ```
   git clone https://github.com/USERNAME/job-search-pipeline.git
   cd job-search-pipeline
   ```

2. Confirm Python works. The examples below use macOS and Linux commands. On Windows, type `py` where they say `python3`, and `copy` where they say `cp`.

   ```
   python3 --version
   ```

3. Run the self-test. It needs no network access and no configuration.

   ```
   python3 test_screen.py
   ```

   The last line should read `14/14 checks passed`.

## Configuration

Three files hold everything specific to you. All three are listed in `.gitignore`, so your copies stay on your machine.

**1. Secrets: `.env`.** Copy `.env.example` to `.env` and fill in your email settings. For Gmail, turn on 2-Step Verification, create an app password at https://myaccount.google.com/apppasswords, and paste it into `SMTP_PASS` without spaces. Values already set in your system environment take precedence over the file.

**2. Screening rules: `screening_local.py`.** Copy `screening_example.py` to `screening_local.py` and edit it. The example describes a fictional learning-and-development professional near Denver, Colorado. Every setting has a comment explaining what it does. The ones to change first:

| Setting | What it controls |
|---|---|
| `MIN_SALARY` | Postings whose published band tops out below this are dropped. Postings with no band are kept. |
| `TITLE_SIGNALS`, `TITLE_KILL` | Words a title must contain, and words that reject it. |
| `HELD_FIELDS`, `NEVER_HELD_FIELDS`, `TARGET_FIELDS`, `YEARS_GATE` | How years-of-experience requirements are judged. |
| `BODY_KILL` | Requirements you cannot meet, each with the label the digest prints. |
| `HOME_STATE_PATTERN`, `LOCAL_PLACES`, `LOCATION_KILL` | Your home state, the towns you would commute to, and the ones you would not. |

The faculty settings at the bottom apply only to boards you tag `"lane": "faculty"`. Leave those boards out if you do not want that lane.

**3. Boards to watch: `boards.json`.** Build it with the probe scripts, or copy `boards.example.json` and edit it by hand. The example file lists three public boards (two on Greenhouse, one on Workday) so you can try the monitor before building your own list:

```
cp boards.example.json boards.json
python3 job_monitor.py --report
```

To watch your own employers:

- Greenhouse, Lever, and Ashby: put company slugs in a text file, one per line (see `slugs.example.txt`), then run `python3 probe_boards.py slugs.txt`. The slug is the last part of the employer's board URL, for example `boards.greenhouse.io/SLUG`.
- Workday: open the employer's careers page, follow it to the job listings, and copy the URL if it contains `myworkdayjobs.com`. Put the URLs in `workday_urls.txt` (see `workday_urls.example.txt`) and run `python3 probe_boards.py --workday workday_urls.txt`.
- Other vendors: copy `ats_candidates.example.json` to `ats_candidates.json`, add entries using the host names from the employers' careers pages, and run `python3 probe_ats.py`. Use `--dry` to test without changing `boards.json`.
- Indeed: add `{"slug": "indeed-alerts", "ats": "indeed_email", "quiet_ok": true}` to `boards.json` and send Indeed job alerts to the mailbox set in `.env`.

The probes keep only the boards that answer with at least one posting. Some employers block all non-browser clients at their content delivery network; those boards will fail every probe and need email alerts instead.

## Usage

Check that email works before relying on the schedule:

```
python3 job_monitor.py --test-email
```

Seed the list of seen postings. The first run records everything currently open and sends nothing, so later digests contain only new roles:

```
python3 job_monitor.py
```

See everything open right now that passes your rules, without touching `seen.json`:

```
python3 job_monitor.py --report
python3 job_monitor.py --report --from-cache    # re-screen the last pull, no network
```

Record applications so those postings stop appearing:

```
python3 job_monitor.py --applied "https://example.com/jobs/123" --title "Learning Manager" --company "examplecorp"
python3 job_monitor.py --applied "https://example.com/jobs/123" --outcome rejected
python3 job_monitor.py --applications
```

Schedule the nightly run.

Windows (Task Scheduler), replacing the path with your folder:

```
schtasks /Create /TN JobMonitor /SC DAILY /ST 03:00 /TR "C:\path\to\job-search-pipeline\run_monitor.bat"
```

macOS or Linux (cron):

```
0 3 * * * cd /path/to/job-search-pipeline && /usr/bin/python3 job_monitor.py >> monitor.log 2>&1
```

`run_monitor.bat` changes to its own folder before running, because the monitor reads and writes its files next to itself. Output from each run is appended to `monitor.log`.

## Project layout

```
job-search-pipeline/
  job_monitor.py              Nightly monitor: pull, screen, diff, digest, email
  ats_adapters.py             Pullers for Workable, Eightfold, Oracle, SuccessFactors, iCIMS, Phenom, Madgex
  indeed_email.py             Reads Indeed job-alert emails over IMAP
  envfile.py                  Loads .env into the environment
  probe_boards.py             Finds Greenhouse, Lever, Ashby, and Workday boards
  probe_ats.py                Validates boards for the vendors in ats_adapters.py
  screening_example.py        Example screening profile (copy to screening_local.py)
  test_screen.py              Offline regression checks
  run_monitor.bat             Windows wrapper for the scheduled task
  .env.example                Template for secrets and settings
  boards.example.json         Example board list
  ats_candidates.example.json Example input for probe_ats.py
  slugs.example.txt           Example input for probe_boards.py
  workday_urls.example.txt    Example input for probe_boards.py --workday
  fixtures/                   Sample Indeed email for testing the parser
  docs/sample_digest.md       Sample output
```

Files the monitor creates at run time (`seen.json`, `applied.json`, `raw_jobs.json`, `digest.md`, `monitor.log`) are excluded by `.gitignore` because they hold your search history.

## My contributions

I designed and built this pipeline for my own job search in 2026. What it adds beyond a basic job-feed reader:

- **One record for eleven vendors.** Adapters that turn each vendor's JSON, HTML, or RSS into the same record, including Workday's paginated POST API and Oracle site codes that are not published anywhere.
- **Title-first screening.** Screening on the title before fetching descriptions, which keeps requests to large boards in the single digits.
- **Workday location anchors.** Recovering the full location set when Workday's search listing collapses it to "2 Locations", so a nationwide remote option behind a headquarters address is found.
- **Experience gates.** Reading the text around each "N years" requirement and judging it against fields held, fields never held, and target fields. A long requirement in a target field goes to a "stretch" section; the same requirement in a field never held is withheld and listed for review.
- **Remote and residency checks.** Treating a role as remote only when the posting states a remote arrangement, and reading residency clauses so a "remote" role limited to other states is caught.
- **An auditable filter.** Every rejection based on a judgement about the candidate is listed in the digest with a plain-English reason.
- **Failure you can see.** Daily status emails and a per-board health table, so a board that stops answering, or a run that never happened, shows up the next morning.
- **Faculty lane.** A second rule set for full-time online teaching roles, with credential matching and flags for schedule language that could conflict with another job.
- **Release cleanup.** For this public version, every personal setting (target titles, salary floor, home area, employer list, email account) moved out of the code into `screening_local.py`, `boards.json`, and `.env`, with example files in their place.
